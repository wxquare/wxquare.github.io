# /organize-posts - 整理博客文章结构

本技能只描述扫描、分析和报告流程。开始前读取 [`AGENTS.md`](../../../AGENTS.md) 第 3、4、7、10、11 节，以及 `.agents/config/post-categories.json`。

## 执行步骤

1. **扫描文章**

```bash
find source/_posts -name "*.md" -type f
```

2. **解析元数据**
   - 提取每篇文章的 Front Matter、分类、标签、日期和文件路径。
   - 用注册表将路径映射到主分类；不要在本技能中维护分类集合。

3. **执行检查**
   - 依据 `AGENTS.md` 判断目录归属、Front Matter、命名、标签、图片路径和代码块是否符合规范。
   - 识别重复主题、可合并内容、可拆分内容和需要更新的文章。
   - 对每一项建议记录文章标题、当前路径、建议路径或动作以及判断依据。

4. **生成报告**

```text
📊 博客文章整理报告

📈 统计信息：
- 总文章数：X篇
- 分类分布：按 post-categories.json 中的 categories 输出
- 标签分布：按使用次数排序

🔄 建议移动的文章：
1. [文章名]
   当前位置：[路径]
   建议位置：[路径]
   原因：[引用 AGENTS.md 相关规则]

🔗 建议合并的文章：
1. [文章1] + [文章2]
   原因：[说明]

✂️ 建议拆分的文章：
1. [文章名]
   原因：[说明]

⚠️ 需要更新的文章：
1. [文章名]
   最后更新：[日期]
   原因：[说明]
```

5. **生成索引**
   - 按注册表中的主分类生成 `.Codex/indexes/by-category.md`。
   - 生成 `.Codex/indexes/by-tag.md` 和 `.Codex/indexes/by-date.md`。
   - 索引中使用文章实际 Front Matter 展示名和源文件路径。

## 使用场景

- 定期整理
- 新增多篇文章后
- 重构博客结构前
- 准备归档旧文章时

移动或批量修改前先保留可回滚状态，并按 `AGENTS.md` 的源码边界检查内部链接和图片引用。
