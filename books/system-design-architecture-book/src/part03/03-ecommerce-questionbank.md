## 电商平台架构与领域边界

### Q-ECOM-ARCH-01：如何划分电商平台的核心领域与系统边界？

#### 元信息

| 项目 | 内容 |
| --- | --- |
| 题目编号 | Q-ECOM-ARCH-01 |
| 时长 | 30 分钟 |
| 难度 | 进阶 |
| 场景 | 电商 |
| 题型 | 完整系统设计 |
| 能力标签 | 领域建模、系统边界、架构表达 |

#### 题干与约束

请为一个中大型电商平台划分核心领域与系统边界。平台需要支持商品展示、库存管理、营销计价、购物车、订单、支付和履约，并允许后续接入商家与运营能力。

#### 候选人作答任务

说明你如何按业务语言、数据所有权和变化节奏划分边界，画出主要依赖关系，并解释交易主链路中的同步协作、异步事件和权威状态。

#### 推荐作答顺序

先澄清平台模式、交易规模和核心成功指标，再识别商品、库存、营销计价、购物车结算、订单、支付和履约等领域，随后说明数据归属、接口协作、失败边界和演进方向。

#### 答案骨架

候选人应以限界上下文而不是技术组件划分系统。商品提供可售事实和快照来源；库存管理可售量与预占确认；营销和计价负责规则与试算；购物车和结算组织购买意图；订单沉淀交易承诺；支付处理资金状态；履约处理发货与售后。跨域协作应明确哪些需要同步确认，哪些通过事件推进，并为超时、重复和最终一致设计补偿路径。

#### 评分锚点

基础回答能够列出主要系统。较好回答能够区分领域职责、权威数据和主链路依赖。优秀回答能够解释边界取舍、避免共享数据库、处理跨域一致性，并说明商家、运营和规模增长后的演进。

#### 递进追问

商品价格变更后，购物车、订单和搜索结果分别应如何更新？库存预占成功但订单创建失败时，谁负责恢复？平台从自营扩展到多商家后，哪些边界需要调整？

#### 常见失分点

按技术层而不是业务能力拆分；多个系统共同写同一份核心状态；没有说明订单、库存和支付的协作语义；把消息队列当作一致性问题的唯一答案。
