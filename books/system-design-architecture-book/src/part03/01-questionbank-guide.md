# 第 37 章 系统设计题库：使用说明、双索引与训练路线

本题库将系统设计训练拆成可重复练习、可复盘、可评估的题卡。每张题卡围绕一个明确能力点组织，并使用相同的作答顺序、评分锚点和复盘清单，帮助候选人与面试官建立共同语言。

## 题库定位

题库服务于系统设计面试训练，不替代前文对方法论、领域设计和基础设施的完整讲解。候选人应通过题卡识别题目的核心矛盾，再回到关联正文补足原理、边界和工程细节。

## 候选人训练模式

候选人可先选择难度与时长，再按题卡的作答任务限时完成。练习结束后，对照答案骨架确认遗漏的设计维度，用评分锚点判断答案深度，并把失分原因记录在复盘清单中。

短时练习强调需求澄清和表达结构；长时练习要求形成完整架构、数据流、失败处理和演进方案。每次训练应保留题目假设，避免复盘时把未澄清的条件误当作固定要求。

## 面试官评估模式

面试官可根据候选人的作答顺序、关键假设和取舍依据进行观察。评分不只看是否提到某个组件，还要看候选人能否说明权威状态、主链路、故障后果和技术选择的代价。

递进追问用于确认候选人是否能够在约束变化时调整方案，而不是复述预设答案。面试官应优先追问候选人主动提出的假设、风险和边界。

## 统一答题框架

所有题卡按以下六个步骤组织：

| 步骤 | 中文说明 |
| --- | --- |
| requirements and boundaries | 明确业务目标、核心用户、成功指标、约束条件、非目标和外部依赖，先界定要解决什么。 |
| scale and capacity | 估算用户量、峰值流量、读写比例、数据增长、延迟目标和容量余量，说明数量级如何影响设计。 |
| interfaces and data | 划分服务职责，定义关键接口、核心实体、状态归属、读写模型和事件契约。 |
| normal path | 从入口开始说明正常请求如何流转，标出同步调用、异步处理、持久化和用户可见结果。 |
| failure handling | 讨论超时、重试、幂等、降级、数据补偿、监控告警和人工处理路径。 |
| trade-offs and evolution | 解释方案的收益与代价，说明当前边界，以及流量、业务或组织变化后的演进方向。 |

作答时不必机械逐字念出步骤，但应让面试官能够清楚判断每个维度是否已经覆盖。

## 题目标签与难度

题卡使用场景、能力标签、难度、练习时长和题型标注检索范围。能力标签描述主要考察点，场景描述业务语境，题型区分短追问、专题设计和完整系统设计。

| 难度 | 定义 |
| --- | --- |
| 基础 | 能在明确场景下澄清需求、给出主链路，并说明常见组件的职责与基本风险。 |
| 进阶 | 能将容量、一致性、可靠性和数据边界串成完整方案，并在追问下解释取舍。 |
| 高级 | 能处理复杂约束、跨域协作和演进问题，主动说明组织边界、成本和长期治理。 |

| 时长 | 练习目标 |
| --- | --- |
| 10 分钟 | 完成范围澄清、核心判断和结构化表达。 |
| 20 分钟 | 补全主链路、关键数据和主要风险。 |
| 30 分钟 | 形成专题系统的可讨论设计，并接受递进追问。 |
| 45 分钟 | 完成端到端系统设计、容量推导、故障处理和演进取舍。 |

## 训练路线

建议先用基础题卡训练统一答题框架，再进入通用专题题卡，最后完成电商专项与模拟面试。每一阶段都应从短时练习开始，确认表达顺序稳定后再增加约束、时长和追问强度。

一条可执行的训练路线是：先完成 10 分钟需求澄清题，再完成 20 分钟容量与数据题，然后完成 30 分钟领域边界题，最后进行 45 分钟综合设计和面试复盘。对于反复失分的能力标签，应回到关联正文复习后重新限时作答。
