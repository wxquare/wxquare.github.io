## 需求澄清与范围控制

### Q-GEN-SCOPE-01：设计一个系统前，你会澄清哪些需求和边界？

#### 元信息

| 项目 | 内容 |
| --- | --- |
| 题目编号 | Q-GEN-SCOPE-01 |
| 时长 | 10 分钟 |
| 难度 | 基础 |
| 场景 | 通用 |
| 题型 | 短追问 |
| 能力标签 | 需求澄清、表达 |

#### 题干与约束

面试官要求你“设计一个系统”，但尚未给出业务目标、用户规模、数据特点和可靠性要求。请说明你会先澄清哪些问题，以及这些问题会如何影响后续设计。

#### 候选人作答任务

在限定时间内按优先级列出澄清维度，区分核心目标、约束条件与非目标，并选择两个问题说明其对架构决策的影响。

#### 推荐作答顺序

先确认服务对象和业务结果，再确认规模、读写模式、一致性与延迟要求，随后确认合规、安全、地域和外部依赖，最后收束为本次设计的范围与非目标。

#### 答案骨架

候选人应覆盖业务目标与成功指标、核心用户路径、峰值流量与数据增长、读写比例、延迟与可用性目标、一致性要求、权限与审计、外部依赖，以及明确不在本次设计范围内的事项。每项澄清都应服务于后续容量、数据模型或故障处理决策。

#### 评分锚点

基础回答能够先问目标和规模，不直接堆叠组件。较好回答能够将澄清项与缓存、存储、同步异步或一致性选择关联。优秀回答能够主动说明不同答案会改变哪些架构边界，并明确非目标。

#### 递进追问

如果业务方只回答“用户很多、必须稳定”，你会怎样继续量化？如果核心交易必须正确，但报表可以延迟，你会如何划分一致性边界？

#### 常见失分点

直接给出技术方案；只问用户量而忽略业务目标；把高可用和强一致当成所有链路的默认要求；没有说明非目标。
