# 博客文章审查与质量评分标准

标准版本：1.0（2026-10-13）。适用于 `source/_posts/` 中的博客文章；书稿评审可参考内容维度，但必须遵循自身的章节规范，不套用博客 Front Matter 和标题要求。

本文件是文章审查清单、发布门槛、质量评分和评审报告的唯一标准。人工评审、`review-post` 和专项助手均引用本文件，不另外维护权重、分档或评分规则。

目录、格式、引用和协作规则以 [AGENTS.md](../AGENTS.md) 第 3、4、10、11 节为准。本文件负责如何检查和评价这些规则，不复制它们的具体要求。传播效果、访问量和 SEO 排名单独观察，不计入内容质量分。

## 审查流程

1. 确认目标读者、文章类型，以及文章承诺的阅读收益。
2. 检查发布门槛，记录通过、未通过或待核验。
3. 按检查清单审查全文；不适用的项目写明原因。
4. 按六个维度评分，每项给出正文位置、证据和扣分原因。
5. 输出评审报告，优先列出最影响读者的三个问题。
6. 修改后复核问题及受影响的内容，记录复核结果。

脚本负责检查可机械判断的格式、路径和构建；AI 辅助发现逻辑、表达和证据问题；关键代码、性能数字和技术结论通过实际运行、一手来源或人工核验确认。构建成功不能证明技术结论正确。

## 发布门槛

每项使用“通过 / 未通过 / 待核验 / 不适用”，不适用必须说明原因。

| 检查项 | 未通过的情形 |
|---|---|
| 核心结论 | 关键概念、因果解释或建议存在影响阅读收益的技术错误 |
| 来源与数字 | 核心引用不支持相邻结论，或将未经说明的假设、性能和经验数字写成普遍事实 |
| 核心示例 | 承诺可运行的核心代码无法运行，或将缺少关键步骤的伪代码当作完整实现 |
| 版本与适用边界 | 版本差异或环境条件影响核心结论，却未说明 |
| 公开边界 | 含敏感信息、未经授权的内部材料或不符合仓库来源与再分发规则的内容 |
| 发布完整性 | 违反适用的仓库强制规则，构建失败，或关键链接、图表和页面无法正常展示 |

任一项未通过，发布结论为“阻塞”；影响核心结论的项目待核验，发布结论为“待核验”。分数不能抵消发布门槛问题。外链因网络限制无法访问时记录待核验，不能直接断言链接失效。

## Review checklist

检查状态使用“通过 / 有问题 / 待核验 / 不适用”。勾选仅表示已检查且通过，不以勾选数量计算总分。

### 读者与内容结构

- [ ] 目标读者和前置知识明确，标题与正文交付一致。
- [ ] 开头说明问题、适用场景和读者能够获得的收益。
- [ ] 章节顺序服务于理解或操作，关键推理没有跳步。
- [ ] 标题层级、目录和命名符合 `AGENTS.md`；博客正文不重复文章标题。
- [ ] 结论或行动建议清楚；不强制所有短文设置独立引言、总结章节。
- [ ] 内容没有通过重复观点、堆砌术语和无关章节增加篇幅。

### 技术准确性与边界

- [ ] 术语一致，概念、代码逻辑和因果解释正确。
- [ ] 说明影响结论的版本、环境、依赖和适用前提。
- [ ] 明确区分事实、作者经验、场景推导和预测。
- [ ] 绝对化表述有充分支撑，讨论必要的反例和失败条件。
- [ ] 时效性结论已核验，记录实际核验日期和版本；不将全文修改日期当作技术核验日期。

### 证据与引用

- [ ] 关键结论有直接相关的一手来源、实验或明确标注的推导。
- [ ] 引用直接支持相邻陈述，正文与文末条目对应，格式符合 `AGENTS.md`。
- [ ] 数字说明是假设、测量结果或来源数据；测量包含必要的环境、负载和方法。
- [ ] 来源、作者、版本等元数据真实，不补造引用信息。
- [ ] 代码、数据和架构图注明来源，符合公开和再分发边界。

### 示例与实用性

- [ ] 声称可运行的示例说明环境、依赖、输入和预期结果，并记录实际验证情况。
- [ ] 片段或伪代码明确标注，不把示意代码视为完整工程。
- [ ] 关键步骤完整，说明必要的错误处理、失败分支和排查方法。
- [ ] 例子能够解释核心概念或帮助做决策，内容没有示例时说明原因。
- [ ] 新增可运行实验遵循 `AGENTS.md` 的独立仓库边界。

### 表达与发布质量

- [ ] Front Matter、分类、标签、链接、图片路径和代码块符合 `AGENTS.md`。
- [ ] 语言清楚，必要术语有解释，段落和表格便于阅读。
- [ ] 图表、代码、公式和正文一致，图片有帮助理解的替代说明。
- [ ] 内部链接、引用锚点和关键资源可用，外链失败区分失效与访问限制。
- [ ] 已执行适用的仓库校验，记录命令、结果或未执行的原因。
- [ ] 标题和摘要准确表达内容，内部链接有实际阅读价值。

字数、标签数量、图表数量和引用数量本身不代表质量；不设置通用最低字数，不为增加数量奖励分数。

## 按文章目的调整审查重点

文章类型由阅读目标决定，与目录分类独立。混合文章指定一个主类型，并检查影响目标的其他类型要求；六维权重保持一致。

| 类型 | 重点核验 |
|---|---|
| 实践教程 | 环境、完整步骤、预期结果、验证记录、失败处理与必要的回退方案 |
| 原理综述 / 面试文章 | 概念关系、简化解释的边界、误区、反例与知识迁移能力 |
| 系统设计 | 问题和约束、容量假设、方案比较、一致性与故障模式、成本和适用边界 |
| 研究 / 观点文章 | 事实与推导的区分、来源覆盖、反证、不确定性与独立判断 |

不因观点文章缺少代码扣分，也不因教程缺少原创理论扣分；评价它是否充分完成声明的阅读目标。

## 质量评分

### 六个维度

| 维度 | 权重 | 评价依据 |
|---|---:|---|
| 技术准确性 | 30 | 概念、代码和因果解释正确；版本、前提和边界清楚 |
| 证据与可验证性 | 20 | 关键结论有直接支持，来源可追溯，实验和推导可检查 |
| 读者收益 | 20 | 完成声明的阅读目标，帮助读者理解、操作或决策 |
| 深度与独立判断 | 15 | 解释原因、权衡、反例和失败场景；提供有依据的综合判断 |
| 结构与表达 | 10 | 路径清楚、推理连贯、表达简洁，示例与图表帮助理解 |
| 发布与维护质量 | 5 | 格式与渲染可靠，资源可用，时效信息和维护边界明确 |

### 分值锚点与计算

每个维度使用 0–4 的整数原始分，禁止只凭整体印象评分。

| 原始分 | 锚点 |
|---|---|
| 0 | 相关内容缺失，或存在使该维度失去可信度的严重问题 |
| 1 | 有相关内容，但明显缺口影响理解、使用或判断 |
| 2 | 基本合格，足以完成文章声明的目标，但仍有具体不足 |
| 3 | 解释充分，证据、边界或组织方式支持可靠使用 |
| 4 | 在充分完成目标的基础上，提供可复用的方法、验证或有证据的洞见；该维度没有已知实质缺口 |

维度得分 = 原始分 ÷ 4 × 权重；总分为六项得分之和，满分 100。使用未舍入的维度得分计算总分，最后保留一位小数。

每项记录正文位置、支撑证据和不足。影响维度判断的证据未核验时，该维度标为“待核验”，不填猜测分、不按零分处理、不重新分配权重；此时只列已评维度得分，暂不提供总分或分档。

单条检查项可以不适用，但六个评分维度均需按文章目标评价。技术准确性在观点文章中包括事实基础和推理正确性，证据维度包括推导依据；不存在整项默认满分。

### 初始分档

| 总分 | 内容评价 |
|---|---|
| 85–100 | 重点推荐候选 |
| 70–低于 85 | 达到发布质量标准，有明确改进项 |
| 低于 70 | 优先修改，暂未达到发布质量标准 |

发布结论单独给出：门槛全部通过且总分至少 70，才可判为“可发布”；门槛通过但低于 70 为“需修改”；未通过门槛为“阻塞”；核心门槛或评分待核验为“待核验”。分档和推荐均不能跳过门槛。

这些分档是初始约定。先选五篇不同类型文章试评，同一内容版本由不同评审者独立评分；对明显差异回看证据和锚点，校准标准。标准变化必须更新版本，跨版本分数不直接当作质量提升。

最影响读者的三个问题（不足三个时按实际数量）：
- 严重程度：阻塞 / 一般问题 / 优化建议
- 位置、问题、证据、对读者的影响、具体修改建议

复核记录：问题修复情况、受影响维度和门槛的变化

专项助手仅评估其实际覆盖的维度，并明确未覆盖部分。技术审查或 SEO 审查的局部结论不能冒充完整六维总分。

## 维护规则

- 核心标准仅在本文件修改；模板、技能和助手只维护执行方式并链接到这里。
- 单篇评审报告属于临时工作记录，默认放在 `AGENTS.md` 规定的任务工作目录中，不在文章正文添加自评分。
- 关键结论、代码、依赖版本或文章阅读目标变更后重新评审；局部文字调整可只复核受影响项。
- 定期检查链接和时效性内容，复核日期只代表实际检查过的范围。
- 观察门槛问题数、待核验项和修复效果；不以平均分上升替代逐篇问题修复。
