## 第 26 章内容设计

章节标题：**持续进化的生活 Agent：从日常反馈到可信能力闭环**。

本章讨论的是一个长期运行、但受权限与风险边界约束的个人生活 Agent。它可以辅助整理日历、邮件、购物清单、家庭待办和个人知识；它不应在缺少明确授权时自行发送邮件、支付、购买、处理健康或金融决策。

章节采用“每周生活回顾 Agent”作为贯穿案例：Agent 汇总一周的日历、任务、邮件和用户反馈，提出可审计的改进建议；所有能力变化必须经评估、审批和可回滚发布，而非把一次对话直接写回 Prompt 或记忆。

### 26.1 长期运行的生活 Agent：范围、授权与非目标

- 区分“给出建议”“准备草稿”“执行外部动作”三种权限等级。
- 明确个人隐私、最小权限、显式确认和敏感场景禁区。
- 说明记忆、日志和学习不是同义词：保存经历不等于能力得到验证的提升。

### 26.2 以证据为先的运行数据模型

- 保留不可变的原始轨迹：输入、上下文快照、工具调用、结果、用户修订与失败信号。
- 将每次运行整理为结构化经验卡：任务、环境、策略、结果、证据、反证和不确定性。
- 对隐私数据采用最小化采集、脱敏、保留期和删除机制。

### 26.3 三层评估：结果、过程与质量验证

- 结果评估：任务是否真正完成、是否节省用户时间。
- 过程评估：工具是否被正确调用、关键确认是否缺失、是否越权。
- 质量验证：建议或自动化是否正确、可解释、稳定，且不损害已有成功场景。
- 区分用户显式反馈、隐式修订信号和自动校验信号，避免把单次偏好误判为通用规律。

### 26.4 更新路由：知识、Prompt/Skill、工作流与 Harness

经验必须先分类，再进入合适的更新通道：

- 稳定事实与用户确认的偏好，进入有来源和版本的知识层。
- 可复用的任务策略，形成最小差异的 Prompt 或 Skill 更新候选。
- 重复的跨工具任务，形成带前置条件、动作和后置验证的工作流候选。
- 权限、重试、失败恢复、审计等运行问题，进入 Harness 改进候选。

每项候选变更都应携带触发它的证据、适用边界、潜在反例和回归测试集；不将原始用户轨迹直接当作可执行规则。

### 26.5 受控发布闭环

闭环为：运行轨迹与反馈 → 跨轨迹证据聚合 → 更新提案 → 留出集回归与安全检查 → 人工审阅 → 小流量试运行 → 正式发布或回滚。

本节说明版本号、变更记录、指标阈值、回滚条件和人工批准点，使“持续进化”成为可治理的软件发布过程，而不是不可观察的自我修改。

### 26.6 案例：每周生活回顾 Agent

通过日历、待办、邮件与购物清单的组合案例展示：

1. 生成周回顾和下周行动建议；
2. 收集用户接受、修订、拒绝和遗漏等反馈；
3. 将多次失败聚合为假设，而非由单个样本直接学习；
4. 产出知识更新、Skill 更新或工作流改造提案；
5. 使用保留的历史任务验证改进，并在必要时回滚。

案例只展示模拟数据、伪接口和审批边界，不接入真实账号或执行不可逆外部操作。

### 26.7 上线检查清单与度量

以成功率、人工接管率、越权拦截率、用户修订率、回归通过率和回滚恢复时间为核心指标，并给出发布前检查清单。

## 与既有章节的关系

- 第 10 章提供上下文证据、状态和预算的基础。
- 第 11 章提供 Harness 的控制循环、恢复和审计能力。
- 第 13–17 章分别承接工具、知识、记忆、编排和评估治理；第 26 章只把这些能力组合为长期运行的生活场景，不重复其底层原理。
- 第 25 章个人知识管理 Agent 提供知识工作流案例；第 26 章进一步讨论如何让此类 Agent 在反馈驱动下安全演进。
- 第 27 章转向研究型 Agent 的能力边界与系统综述，避免与生活场景混杂。

## 参考与写作原则

第 26 章借鉴《AI Agent Book》第 9 章关于持续进化的核心方法：区分记忆与学习、从多条轨迹中建立证据、为变更设置独立回归验证、采用人工审阅与渐进发布/回滚。书稿将以原创中文表述重构这些方法，并针对个人生活场景补充权限与隐私边界。
